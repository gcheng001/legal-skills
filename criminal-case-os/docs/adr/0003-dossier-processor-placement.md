# criminal-dossier-processor 归属准备组，作为可选前置

## 背景

criminal-dossier-processor 是外部引入的卷宗PDF拆解工具（2026-05-29原版，2026-07-04接入），把混编卷宗PDF拆成12类目独立PDF + 索引目录。它在体系中的归属位置需要明确：它不是通用的案件落地步骤（如 case-git-init / case-info-extract），却是阅卷的理想前置。

## 决策

挂在刑事OS的**准备组**作为**可选前置**（交互菜单「0.5 卷宗拆解」），与通用准备步骤并列但标注"可选·阅卷前物料准备"。同时保留为独立可触发的 skill（触发词"卷宗拆解/拆卷宗"等，不依赖刑事OS）。

## 理由

dossier 的产出（12类目PDF + 00_索引目录.md）紧贴"准备组→阅卷"的数据流向，是 `criminal-case-review` 的理想输入。放在准备组让流程连贯。

但 dossier **非每案必需**：若卷宗本身已分类、或为结构化电子卷宗，可直接进入阅卷。因此标"可选"不强制，菜单编号用 0.5 暗示其辅助性质。

保持独立 skill 身份，使律师不进刑事OS也能单独拆卷宗（一次性整理场景）。

## 强制确认点

dossier 的分类基于关键词匹配，置信度低于50%会在索引中标记。分类错误会导致阅卷漏材料，属于 Hard Fail 级风险。因此**拆解完成后律师必须复核 `00_索引目录.md` 的分类**，此确认点不可省略。

## 备选方案（被拒绝）

- **内嵌进 criminal-case-review**：被否，耦合会使拆解故障卡住阅卷，且 dossier 有独立使用场景。
- **完全独立不挂菜单**：被否，律师触发刑事OS时不会想到还有个单独的拆卷工具，流程会断。
