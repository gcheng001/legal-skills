# 刑事文书格式规范

> **用途**：统一刑事法律文书的 Word 排版格式标准，确保全系统各 skill 导出的刑事文书风格一致、专业规范。
> **适用范围**：供 criminal-case-os 全系统子skill调用。本规范是**全系统刑事文书的统一格式基准**，各 skill 导出 Word 时一律引用本规范。
> **一致性要求**：与 criminal-case-review（刑事阅卷笔录）的格式保持完全一致。

---

## 一、格式规范总则

| 项目 | 规范要求 |
|------|---------|
| 全文字体 | 仿宋_GB2312 |
| 大标题（文书名称及"一、二、三"章节标题） | 二号(22pt)，加粗，居中 |
| 子标题（"1、2、3"） | 小四号(12pt)，加粗 |
| 正文 | 四号(14pt)，不加粗，1.5倍行距，首行缩进2字符 |
| 表格表头 | 黑体，加粗 |
| 表格内容 | 仿宋 |
| 页边距 | 上下左右均 1.25 英寸 |
| 页码 | 底部居中 |
| 落款 | 不可遗漏 |

---

## 二、各要素详解

### 1. 字体
- **全文统一使用仿宋_GB2312**（表头除外，表头用黑体）。
- 中英文、数字均使用同一字体族，保持视觉统一。

### 2. 标题层级
- **大标题**（文书名称如"辩护词""法律意见书"，以及"一、""二、""三、"等一级章节标题）：二号字(22pt)，加粗，居中。
- **子标题**（"1、""2、""3、"等次级标题）：小四号(12pt)，加粗。
- 标题层级必须有明显字号区分，**严禁所有标题使用同一字号**。

### 3. 正文
- 四号字(14pt)，不加粗。
- **1.5 倍行距**。
- **首行缩进 2 字符**。

### 4. 表格
- 表头：黑体，加粗。
- 表格内容：仿宋。

### 5. 页面与页码
- 页边距：上、下、左、右均为 **1.25 英寸**。
- 页码：置于页面**底部居中**。

### 6. 落款
- 文书末尾的落款（辩护人/律师事务所名称、日期等）**不可遗漏**。

---

## 三、禁止事项（强制）

1. **禁止保留 Markdown 项目符号**（小圆点 `•`/`-`）——须转换为规范的中文序号（一、二、三 / 1、2、3）或正式段落。
2. **禁止保留 Markdown 分隔线**（`---`）——Word 文书中不应出现。
3. **禁止所有标题使用同一字号**——必须体现大标题/子标题的层级差异。
4. **页码禁用 OCR 行号**——页码须为 Word 自动生成的页脚页码，不得沿用 OCR 文本中的行号或扫描页码。

## 五、两层目录规范（v3.3 新增）

> **正式文书与工作底稿必须分文件保存,禁止合并。**

### 5.1 工作底稿（internal）

- **保存路径**:案件目录下专设子目录,如 `intermediate/`、`阅卷笔录/`、`证据审查/`、`辩护方案/`、`sentencing-defense/` 等
- **允许内容**:含表格、勾选、评估符号、模块标签(如【A.2】)、分析过程
- **禁止用途**:禁止直接对外提交;禁止作为呈堂文书使用
- **典型产物**:阅卷笔录、证据分析草稿、量刑计算表、辩护策略草稿

### 5.2 正式文书（external）

- **保存路径**:案件目录下专设子目录,如 `辩护词/`、`sentencing-defense/`、`appeal/`、`intermediate/plea-bargain-strategy-*.md` 等
- **强制要求**:
  - 通篇无内部模块标签(如 `【M1】`、`【A.2】`、`【T2-1】`)、无 emoji、无勾选表格( ☐ ☑ ✓ 等)
  - 通篇无 Markdown 残留标记( `#`、`*`、`>` 等)、无分隔线(`---`)
  - 落款信息一律从案件状态头 `CLAUDE.md` 读取,禁止硬编码
- **必须生成 Word 版(`.docx`)**:正式文书必须同时存在 `.md` 源文件与 `.docx` 转出文件
- **典型产物**:辩护词、量刑辩护意见、上诉状、申诉状、再审申请书、认罪认罚协商策略意见书

### 5.3 双产物结构的典型场景

| Skill | 工作底稿 | 正式文书 |
|-------|---------|---------|
| criminal-case-review | 阅卷笔录.md | — (阅卷笔录本身是工作底稿,不直接对外) |
| criminal-defense-strategy | 辩护策略报告.md | — |
| criminal-sentencing-defense | 量刑计算表.md | 量刑辩护意见.md + .docx |
| criminal-plea-bargain | (内部讨论) | 认罪认罚协商策略意见书.md + .docx |
| criminal-defense-statement | — | 辩护词.md + .docx |
| criminal-appeal | — | 上诉状.md + .docx / 申诉状.md + .docx / 再审申请书.md + .docx |

## 六、Word 版生成规范（v3.3 新增）

> **正式文书必须同时存在 `.md` 源文件与 `.docx` 转出文件。**

### 6.1 字体与排版

| 项目 | 规范要求 |
|------|---------|
| 全文正文字体 | 仿宋_GB2312(四号 14pt) |
| 大标题(文书名称与"一、二、三"章节标题) | 二号(22pt),加粗,居中 |
| 子标题("1、2、3"等次级标题) | 小四号(12pt),加粗 |
| 表格表头 | 黑体,加粗 |
| 表格内容 | 仿宋 |
| 行距 | 1.5 倍 |
| 首行缩进 | 2 字符 |
| 页边距 | 上、下、左、右均 1.25 英寸 |
| 页码 | 底部居中 |

### 6.2 Markdown 残留复核清单

`.docx` 转出后,必须逐项复核以下 Markdown 残留标记:

- [ ] 无 `#`、`##`、`###` 标题标记
- [ ] 无 `*斜体*` / `**粗体**` 残留
- [ ] 无 `>` 引用块标记
- [ ] 无 `-`、`*` 项目符号
- [ ] 无 `---` 分隔线
- [ ] 无 `` ` `` 代码标记
- [ ] 无 `[文字](URL)` 链接残留
- [ ] 无表格首行 `|---|` 分隔残留

### 6.3 转出工具

- 推荐:`pandoc` 或 `~/.claude/skills/docx` skill
- 转出命令示例:`pandoc input.md -o output.docx --reference-doc=template.docx`
- 转出后立即执行 §6.2 复核清单

## 七、落款规则（v3.3 新增）

> **所有正式文书的落款信息(律师、律所、执业证号、联系电话、当事人)一律从案件状态头 `CLAUDE.md` 读取,禁止硬编码。**

### 7.1 状态头必填字段

落款信息依赖以下状态头字段(详见 `criminal-case-os/CONTEXT.md` 与 SKILL.md 类型继承节):

- `承办律师`(必填)
- `律师事务所`(必填)
- `执业证号`(必填)
- `联系电话`(必填)
- `当事人姓名`(必填)
- `当事人身份证号`(选填)
- `当事人住址`(选填)

### 7.2 缺失处理

- 任一必填字段缺失时,必须立即暂停并提示律师补充,禁止默认占位
- 缺失信息写入工作底稿的「待补字段」,禁止写入正式文书

### 7.3 落款日期

- 落款日期使用**状态头中"案内现在时"对应的日期**或经律师确认的提交日
- 禁止使用系统真实日期(详见 redlines 「案内时间锚定铁律」)
