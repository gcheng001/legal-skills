# CONTEXT — 案件OS（civil-case-os）术语表

> 本文件是纯术语表，不含实现细节。依据 ADR-0004（2026-08-19）建立，随术语沉淀持续更新。

## 人员与角色

| 术语 | 定义 |
|------|------|
| **总控** | civil-case-os 本体：加载全局规则、调度步骤、执行门禁（律师确认/复验/S10）、执行机器活。唯一的"当家人" |
| **律师** | 人类用户高澄。所有"必须确认"门禁的最终拍板人 |
| **专职师傅** | 被派发执行某个动脑环节的 subagent 分身。一次上场只干一件事，带岗位说明书 |
| **借调师傅** | 岗位说明书来自 SuitAgent 原件的专职师傅（DocAnalyzer/EvidenceAnalyzer/Researcher/IssueIdentifier/Strategist/Writer/Reviewer）。只读引用，永不修改原件 |
| **内部提拔师傅** | 岗位说明书来自案件OS自有九步法文档的专职师傅（诉请固定师/请求权基础师/抗辩分析师/要件拆解师/举证责任师/事实认定师/裁判预测师） |
| **主会话** | 律师交互发生的会话。案件讨论、门禁确认、师傅派发的发起地 |

## 干活方式

| 术语 | 定义 |
|------|------|
| **机器活** | 无需法律推理的机械环节：A1建档/A2扫描OCR/A3归档/A5飞书同步/A7状态汇总/Hook。总控直执，不派师傅 |
| **动脑活** | 需要法律推理的环节：A4起至文书交付全部。一律派专职师傅 |
| **派发** | 总控用 subagent 工具把一个动脑环节交给专职师傅执行的行为。prompt 四段：岗位说明书全文＋环节规则与门禁＋案件上下文＋输出契约 |
| **共用档案柜** | 所有案件材料与产出一律写入案件OS案件目录的规矩。SuitAgent 直接办案也不例外，禁止12层新档案柜（除非用户明确要求独立建库） |

## 质检与门禁

| 术语 | 定义 |
|------|------|
| **质检双闸** | 对外交付的两道关：S10管"法条真假"（横），Reviewer管"文书成品质量"（竖）。职责不重叠 |
| **一票否决** | Reviewer 对对外文书（起诉状/答辩状/上诉状/代理词/质证意见/法律意见书）的权力：质检不过即打回重写，律师看到的一定是过了双闸的版本 |
| **门禁时序** | 师傅完成≠步骤完成。律师确认/北大法宝复验在师傅产物之后、步骤过门之前，由总控执行 |
| **【立场参考】** | 召见轨 Strategist 产物的强制标签。带此标签的产物禁止作为 S1-S9 任何步骤的输入 |

## 立场管理

| 术语 | 定义 |
|------|------|
| **中性分析链** | S1-S10 法官视角主链。只回答"法院会怎么判"，立场思维禁止进入 |
| **承重墙** | 中性分析链与立场打法之间的隔离：立场产物只从末端出口（case-stance-exit）流出，不回写主链 |
| **正轨** | Strategist 的唯一正式岗位：立场出口（S10通过后），出立场打法与客户摘要 |
| **召见轨** | 办案中随时单独召唤 Strategist 答疑的通道。产物标【立场参考】，写入 intermediate/ 或备忘录，不入正式分析链 |
