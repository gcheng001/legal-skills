# ADR-0004：专人派发体制（case-os × SuitAgent 融合）—— 基座不动，借调师傅，质检双闸

- **状态**：Accepted（协议已落 `specialist-dispatch.md` 与 `promoted-specialists.md`，SKILL.md v11.4 已载）
- **日期**：2026-08-19
- **决策者**：高澄
- **关联**：`references/specialist-dispatch.md`（派发协议全文）、`references/promoted-specialists.md`（内部提拔师傅说明书）、SuitAgent 本地接入说明（共用档案柜条）

## 背景

用户在实战中使用 SuitAgent（GitHub 移植，11代理协作系统）办数案后反馈：**产出的文书质量、回答的针对性、分析的透彻度、检索的准全度全面优于案件OS**。经拷问确认：优势来源不是某一位代理，而是**专人专岗（subagent 专注单职）的工作方式本身**——每位师傅上场时上下文只装一件事。

同时确认的事实：
1. 案件OS的门禁体系（律师确认/北大法宝复验/S10幻觉校验/状态契约）是 11 个版本迭代出的已验证资产，不可破坏；
2. 用户对案件OS的启动方式更熟悉，明确要求"以案件OS为基础改造"；
3. SuitAgent 原件保持原样可保留 GitHub 上游更新通道；
4. SuitAgent 自身实践：机械工作不派 subagent（其架构决策 #047），工作流从"分析"开始而非"建档扫描"。

## 决策（七条，拷问定案）

1. **基座不动**：案件OS为唯一基座与入口，门禁/S10/复验/状态契约原样保留，改造只换"干活的分身"。
2. **派发边界**：A1建档/A2扫描OCR/A3归档/A5飞书同步/A7状态汇总/Hook 为机器活，总控直执不派师傅；**A4起所有动脑环节一律派专职师傅**。
3. **师傅两路来源**：
   - SuitAgent 借调七位：DocAnalyzer(A4)/EvidenceAnalyzer(A6)/Researcher(S5)/IssueIdentifier(S6)/Strategist(立场出口)/Writer(文书)/Reviewer(质检)——岗位说明书只读引用，原件永不修改；
   - 内部提拔七位：S1诉请固定师/S2请求权基础师/S3抗辩分析师/S4要件拆解师/S7举证责任师/S8事实认定师/S9裁判预测师——用自有九步法文档立岗，配最接近的SuitAgent师傅经验作参考。
4. **质检双闸**：S10 管法条真假（原样）；Reviewer 管文书成品质量——**对外文书一票否决**（闸位：文书生成→Reviewer→律师最终确认→交付），内部分析只提意见。
5. **策略师傅双轨**：正轨=立场出口（S10后）；召见轨=随时可单独召唤答疑，产物必标【立场参考】且**禁入 S1-S9 任何步骤输入**。承重墙：立场思维不渗中性分析链（承 ADR-0003 根判断）。
6. **共用档案柜**：SuitAgent 触发词与全流程能力保留；但直接办案时产出写入案件OS案件目录，不新建12层档案柜（仅用户明确要求独立建库时除外）。此规矩写在其本地接入说明（我们自己的适配层），**不改 SuitAgent 原件**。
7. **未采用角色**：Scheduler（期限由 case-court-sms 承接）、CaseSync（飞书由 case-feishu-sync 承接）、Reporter/Summarizer（Handoff Package 承接汇总，需要阶段报告时可选借调）。

## 首真案验证补记（2026-08-19，莘意vs顺富案）

**验证结果**：v11.4 装载成功但 **0 次派发**——52步70个工具调用全由总控直执，质证意见/A4确认表/S2补正/庭前手册等动脑产物均未派师傅，S10与机器活处理正确。

**缺陷1（已修，commit 45e5b017）**：派发协议是纸面劝导，无结构强制。修复：**派发硬闸**——动脑活产物未经派发不得写入案件目录，豁免须 LOG.md 留痕，绕闸等同 Hard Fail。承 S10 门禁经验：规矩必须做成闸，否则时间压力下必然让路。

**决定8（用户复议）**：Reporter（报告整合师）由"未采纳"改为**采纳**——S10通过后出案件分析报告（深研报告）、开庭前出庭前报告、结案出结案报告、点名随时出；Summarizer 职能并入 Reporter 单一出口。改动动因：用户真案体验中期待"研究报告"产物，原裁掉的假设（Handoff Package 够用）被实战推翻。

## 后果

**正面**：
- 用户实测的质量优势（专人专岗）成建制引入，全流程风格统一；
- 门禁资产零破坏——派发只换执行者，确认/复验/S10 仍由总控把守；
- SuitAgent 上游更新通道保留（原件只读）；
- 两套档案柜合并为一套，双权威混乱消灭。

**负面与代价**：
- subagent 派发有上下文重建成本，每步 token 消耗上升（机器活不派已减一部分）；
- 内部提拔师傅的说明书 v1.0 是初版，需真案校准；
- 召见轨依赖用户自律区分"中性结论"与"立场参考"。

**验证计划**：一个真实案件从 A4 走到文书交付，验证：①派发全链路无断点 ②Reviewer 真能拦劣质文书 ③门禁时序不被师傅绕过 ④状态文件唯一真相。

## 拷问记录（关键问答存证）

- 好在哪：四项全中（文书/答问/分析/检索）→ 病根认定为专人专岗方式本身
- 全流程都换专人？→ 查 SuitAgent 自身实践后定案：机器活除外，A4起全派
- 九步法空缺六步（实为七步）？→ 内部提拔，自有文档立岗
- Reviewer 权力？→ 对外文书一票否决，内部只建议
- Strategist 站位？→ 押后＋随时可召（产物标【立场参考】）
- SuitAgent 去向？→ 原样保留＋共用档案柜（唯一与本 ADR 北极星"统一"相撞后修正的点）
