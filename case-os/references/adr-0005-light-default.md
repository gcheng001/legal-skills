# ADR-0005：默认轻量路（轻量案件OS）—— 三门停、单视图、总控直跑

- **状态**：Accepted（2026-09-15 拷问定案，2026-09-16 落盘实施）
- **日期**：2026-09-15
- **决策者**：高澄
- **关联**：ADR-0004（专人派发体制）、ADR-0003（九步融合）、workflow.md、redlines.md、specialist-dispatch.md

## 背景

首真案验证（ADR-0004 补记）暴露的教训：往案件OS上加师傅没有让它变轻，反而因为确认门禁和派发硬闸更重——真案全程 0 次派发，用户被迫改用 SuitAgent 日常办案。慢的主因是**逐步确认**和**派发硬闸**，不是九步内容本身。九步法中间层（请求权基础、要件拆解、举证责任、事实认定、幻觉校验）仍是案件OS对 SuitAgent 的独特价值，不能丢。

因此本次融合方向反转：**不重写九步正文，只改调度和门禁**，把案件OS日常默认改成轻量路；全链（派师傅 + 双视图 + 逐步确认）降级为升级档。

## 决策（七条）

1. **默认 light**：新案和未声明全链的续办走轻量路；律师明示「升级 / 全链 / 双视图 / 开庭前」才切 full；进行中的 full 旧案保持 full。
2. **轻量路三门停**：A4（当事人与请求）→ 九步包（S1-S10 连续跑完整包确认）→ 对外文书。A5 飞书、A6 证据卡片不再单独拦主链。
3. **总控直跑**：轻量路关闭动脑活派发硬闸，总控直接执行；检索/文书/质检按需借调 SuitAgent，不自动派。
4. **单视图**：轻量路只跑代理这一侧九步目录；S3/S6 仍读对方起诉状或答辩状做抗辩和争点，不另建对侧全套九步。
5. **不切会话**：A→B 不再要求 cc-switch 和新开会话；Git 改为九步包结束后一次提交。
6. **底线不动**：文件不得擅自删改；S10 法条幻觉仍自动阻断进 FINAL；编造事实、跳过三门直接出文书仍是 Hard Fail。
7. **改调度不改正文**：各 case-s* 只加一段轻量路「可连续写下一步，待整包确认」；不修改九步技能的分析正文。

## 与 ADR-0004 的关系

ADR-0004 的派发体制**不废除**，降级为 full 档的干活方式。轻量路下它整体休眠：不派师傅、不硬闸、不逐步确认；升级到 full 时原样恢复。
