# case-filing-gen 起诉状/答辩状生成

## 工作定位

基于S9裁判预测和S6争点矩阵，生成起诉状或答辩状。必须律师确认要点后才生成。

**触发条件**：S10门禁通过后，律师确认
**必须确认**：**是**（确认后才生成）
**门禁**：必须先通过 S10 blocking_result.is_blocked=false 且 can_enter_final=true，方可生成诉讼文书。S10 未执行视同门禁失败。

---

## 执行流程

### 第一步：门禁校验

调用 `check_final_gate.py` 校验 S10 blocking_result：
- `is_blocked=false` 且 `can_enter_final=true` → 通过，继续第二步
- 否则 → **CRITICAL阻断**，不生成诉讼文书

### 第二步：读取九步法文件

- 读取 `intermediate/原告九步法/S1-固定权利请求/`
- 读取 `intermediate/原告九步法/S9-要件归入与裁判预测/`
- 读取 `intermediate/原告九步法/S6-争点矩阵/`

### 第三步：列出要点清单

基于S9裁判预测，列出起诉状/答辩状的要点清单：
1. 诉讼请求
2. 事实与理由
3. 法律依据
4. 证据清单

### 第四步：律师确认

展示要点清单："以下是起诉状要点，请确认是否可以生成"

**红线**：律师确认后才生成。

**重要**（2026-06-09新增）：起草任何法律文书前，必须先确认律师的思路和结构要求，不得按旧框架直接执行。接到"重写""修改"指令时，先回顾之前的讨论记录，确认律师的具体要求再动手。

### 第五步：生成文书

律师确认后，调用 `generate_filing_materials.py` 生成。

### 第六步：修改追问机制

律师修改时，系统必须追问修改原因：
- 诉讼请求写法不同 → 记住律师习惯，下次按此格式
- 诉讼策略变更 → 必须展开讨论，分析利弊
- 质量问题 → 记录律师的改法，沉淀为写作经验

### 第七步：调用Hook

```bash
~/.claude/skills/case-os/scripts/case-post-step.sh [案件路径] filing-gen
```

## 红线

- ❌ **S10 门禁不通过不得生成**
- ❌ **律师确认后才生成**
- ❌ 不得绕过 `check_final_gate.py` 直接调用生成脚本
- ❌ 修改时必须追问原因

# 成套立案文书生成（YAML 驱动）

> **能力来源**：本章节引擎改编自陆凌燕 litigation-docs-generator v2.2.1（MIT License）：
> `scripts/render_docx.py`（YAML 模板渲染引擎）、`scripts/generate_interest_calc.py`（LPR 分段利息计算器，内置 2006—2026-09-20 利率数据库）、`templates/`（7 份格式模板，含来源注记）。

## 与原有九步法能力的关系

| 能力 | 走哪条流程 |
|------|-----------|
| 实体分析（诉讼请求固定、要件归入、争点、裁判预测） | **仍走原九步法 S1-S10 流程**，不变 |
| 单份起诉状/答辩状起草（律师确认要点后） | 原第五步 `generate_filing_materials.py` |
| **成套立案文书**（起诉状+保全+担保+授权等 8 件套一键出） | **新 YAML 引擎**（本章） |

**门禁不变**：成套生成同样属于"生成诉讼文书"，必须先通过 S10 门禁 + 律师确认，方可执行本章流程。九步法产出（S1 诉请、S6 争点、S9 预测）正是新引擎中"诉讼请求 / 事实与理由 / 法律依据"等变量的内容来源。

## 成套文书清单（8 件套，不可遗漏）

| 序号 | 文书 | 格式 | 条件 | 生成方式 |
|------|------|------|------|---------|
| 1 | 利息损失计算表 | .xlsx | 必选 | `scripts/generate_interest_calc.py` |
| 2 | 民事起诉状 | .docx | 必选 | `templates/complaint_template.md` |
| 3 | 诉讼保全申请书 | .docx | 必选 | `templates/preservation_application_template.md` |
| 4 | 担保书 | .docx | 必选 | `templates/guarantee_letter_template.md` |
| 5 | 授权委托书 | .docx | 必选 | `templates/power_of_attorney_template.md` |
| 6 | 法定代表人身份证明 | .docx | 仅原告为公司 | `templates/legal_rep_certificate_template.md` |
| 7 | 律师接待笔录 | .docx | 必选 | `templates/interview_record_template.md` |
| 8 | 委托代理合同 | .docx | 推荐生成 | `templates/retainer_agreement_template.md` |

**注意**：利息计算表排第一（诉讼请求中利息金额的依据）。

## 工作流（五步）

### 1. 收集当事人/案件信息

九步法中间产物已覆盖大部分；仍需补齐：当事人基础信息（自然人身份证号/住址，企业统一社会信用代码/法定代表人/住所地）、管辖法院全称、代理律师信息、利息起算日与截止日、律师费与收款账户（仅委托合同需要）。

### 2. 填 YAML 变量

每份模板 = YAML frontmatter（格式规则，一般不动）+ Markdown 正文（含 `[变量名]` 占位符）。变量以 JSON 传入，key 必须与模板 `[key]` 精确匹配：

```json
{
  "原告姓名/名称": "示例科技有限公司",
  "原告基础信息": "住所地××市××区××路×号，统一社会信用代码：××××××××××××××××××。",
  "原告法定代表人": "张三，执行董事。",
  "原告文书送达地址": "××市××区××路×号",
  "被告姓名/名称": "李某",
  "被告基础信息": "男，19××年×月×日出生，汉族，住××市××区××路×号",
  "管辖法院全称": "××市××区人民法院",
  "案由": "民间借贷纠纷",
  "具体诉请": "偿还借款本金",
  "利息违约金计算方式": "以本金为基数按 LPR 自 ×年×月×日起算至清偿之日",
  "案件事实描述": "……（来自九步法 S8 事实认定）",
  "法律依据": "《中华人民共和国民法典》第六百七十五条、第六百七十六条",
  "year": 2026
}
```

变量注意：
- `[案由]一案` → 案由变量值不带"纠纷"后缀会重复，应填 `民间借贷纠纷` 全称（模板写法为 `[案由]一案` 时填全称）
- 法定代表人三变量映射：complaint/retainer 用 `原告法定代表人`（姓名+职务合写）；legal_rep_certificate 拆成 `法定代表人姓名` + `法定代表人职务`
- 未提供的合同专属字段填"待约定"/"待补充"

### 3. 生成利息计算表（第 1 件）

```bash
python3 scripts/generate_interest_calc.py <输出.xlsx> \
  --principal 25583 --start 2025-01-22 --end 2026-07-10 \
  --lpr-term 1Y --submitter "律师姓名"
```

- 无约定利率时自动查内置 LPR 库（2006-08-19 ~ 2026-09-20 公布值，已核实至最新一期），按利率变化节点分段
- 利息 = 本金 × 天数 × 利率 ÷ 360；相邻同利率段自动合并
- 所有计算列为 Excel 公式（可点击核验），双 sheet：利息计算表 + 利率数据库
- 有约定利率时加 `--rate 3.1`（不分段）；多笔债权用 `--items '<JSON数组>'`

### 4. 渲染 docx 文书（第 2~8 件，逐份调用）

```bash
python3 scripts/render_docx.py templates/complaint_template.md \
  "诉讼文书_[原告简称]_[日期]/02-民事起诉状.docx" \
  --vars '<上述JSON>'
```

- 输出目录不存在会自动创建；文件名按 `01~08` 编号放入 `诉讼文书_[原告简称]_[日期]/` 子目录
- 模板中的样式标签（YAML 定义 + 内联）由引擎自动消费，**不需要也不得**在 vars 里处理格式

### 5. 交叉核对与交付

- [ ] 全部文书人名/名称、金额、日期严格一致
- [ ] 担保书申请人=原告；授权委托书委托人=原告、受托人=律师
- [ ] 原告为企业时才生成法定代表人身份证明
- [ ] 约定利率超 LPR 四倍 → 起诉状与接待笔录加风险提示
- [ ] 法条引用现行有效（未连数据库时文书末尾加"AI 辅助生成，需律师核实"声明——模板已内置 note 标签）

## 格式标签速查（渲染引擎自动消费）

| 标签 | 效果 |
|------|------|
| `#` | 文书标题：18pt 宋体 bold 居中 |
| `##` | 段落标题：16pt 宋体 bold 顶格，前间距 8pt |
| body | 正文：14pt 仿宋，首行缩进 28pt，1.5 倍行距 |
| cizhi | "此致"行：同正文，上方 6pt 间隔 |
| court / `[court]` | 法院名称：顶格不缩进 |
| sign / `[sign]` | 签名行：右对齐 |
| date / `[date]` | 日期行：右对齐，`{year}年  月  日` |
| `[note]` | AI 声明注释 |
| `[meta]` / `[qa_gap]` | 笔录头部元数据行 / Q&A 小间隔 |

排版标准：A4，页边距上3cm 下2.5cm 左3cm 右2.5cm，段间不空行（由 space_before 提供分隔）。改格式只改模板 YAML frontmatter，**不改 Python**。
