# labor-arbitration — 仲裁程序(含裁判者分支)

## 工作定位

**职责**:在L1接案审查完成后,把九步法产物转写为仲裁阶段的文书(申请书/答辩书)、证据目录、一裁终局判断、时限表(写入 labor-os-state.json);**裁判者立场时**替换为双视角合成与裁决书说理草稿。

**前置条件**:
- L1接案审查报告已生成 + labor-os-state.json 存在(stage=l1_intake/completed);
- 九步法**至少 S1(固定请求)、S6(争点)、S7(举证)、S9(预测)**已有产物(JSON frontmatter 优先);
- 若九步法未完成:警告用户,可**降级为"仅时限管理"模式**(只产生时限表 + 提示)。

**必须确认**:是(称谓用申请人/被申请人;申请书/答辩书需"可以出了"才出终稿)。

**执行后 Hook**:否(由劳动OS总控管理)。

**位置层**:L2(劳动覆盖层第二步)。

---

## 执行流程(代理人立场 / stance=claimant or respondent)

### 步骤1 读九步法产物【完成判据:四个关键步骤产物齐备】

读取并校验:
- `intermediate/原告九步法/S1-固定请求/` → JSON claims;
- `intermediate/原告九步法/S6-争点/` 或 `intermediate/被告九步法/S6-争点/` → JSON issues;
- `intermediate/原告九步法/S7-举证/` 或 `intermediate/被告九步法/S7-举证/` → JSON evidence;
- `intermediate/原告九步法/S9-预测/` 或 `intermediate/被告九步法/S9-预测/` → JSON prediction;

**缺一侧/缺步骤**:不直接报错,而是暂停并在 PROGRESS.md + labor-os-state.json 标记,询问用户:① 先驱动 case-os 把缺的补齐;② 或降级模式继续。

### 步骤2 生成仲裁申请书 或 答辩书【完成判据:称谓正确+逐项请求金额计算式】

**称谓铁律**(红线):
- **仲裁阶段全文**:"申请人" / "被申请人";
- **诉讼阶段**(L3之后):"原告" / "被告";
- 案件目录沿用 case-os"原告九步法/被告九步法"命名,**申请人≈原告位**。

**申请人侧(claimant)**:产出《劳动仲裁申请书》,逐项请求含**金额计算式**(如"经济补偿金 = 月工资 × N"),引用九步法 S1 主张项。

**被申请人侧(respondent)**:产出《仲裁答辩书》,针对申请人请求**逐项抗辩**:事实抗辩 → 法律抗辩 → 证据抗辩 → 数额抗辩。

**输出**:`intermediate/劳动覆盖层/L2-仲裁程序/申请书_或_答辩书.md`(JSON frontmatter)。

### 步骤3 证据目录【完成判据:表格+编码+证明目的客观陈述】

输出 `intermediate/劳动覆盖层/L2-仲裁程序/证据目录.md`,表格字段:
| 编号 | 名称 | 来源 | 形式 | 证明目的 |

- **编号清晰**(证据1、2、3…);
- **来源**:取证方(原/被/第三方);
- **形式**:原件/复印件/电子数据/公证书;
- **证明目的**:以**客观陈述**为主,不放主观结论(如"证明原告系被迫离职" → 改为"证明原告在 X 日向被告提交离职申请");

### 步骤4 一裁终局判断【完成判据:三类逐项对照+双通道提示】

对照 `一裁终局与裁审衔接规则.md` 的三类案件:
1. 小额劳动争议(标准:当地月最低工资 × 12);
2. 劳动标准争议(工时/休假/社保);
3. 浙江特别:社保补缴 / 工伤待遇赔付;

逐项判断本案的**哪些请求**落入终局裁决范围,哪些落入非终局。

**双通道提示**:
- 劳动者:**15日内**基层法院起诉;
- 用人单位:**30日内**中院撤裁;
- **混同处理**提醒:同一裁决同时含两类事项的,按非终局处理。

### 步骤5 时限表落地【完成判据:写入state.json deadlines+人读日历】

基于 `仲裁流程时限表.md`,生成**本案 deadlines** 数组写入 `labor-os-state.json.arbitration.deadlines[]`,每条:
```json
{"type": "答辩期|举证期|开庭|审限届满|起诉窗口|撤裁窗口|执行申请", "due_date": "YYYY-MM-DD", "basis": "法条依据", "status": "open|completed|cancelled"}
```

**计算**:
- 受理日 → +5 → 副本送达 / 组庭通知;
- 副本送达日 → +10 → 答辩期;
- 受理日 → +45(+15经审批) → 审限届满;
- 裁决书签收 → +15 → 起诉窗口(终局);
- 裁决书签收 → +30 → 撤裁窗口(终局,用人单位)。

同时输出 **人读版时限日历**:`intermediate/劳动覆盖层/L2-仲裁程序/时限日历.md`。
⚠️ **不写飞书**(红线:不擅自对外通知)。

### 步骤6 文书包存与确认【完成判据:文档包完整+md2word仅在用户确认后转】

将申请书/答辩书、证据目录、时限表包存到 `intermediate/劳动覆盖层/L2-仲裁程序/`。

**md2word** 在用户**最终确认**("可以出了")后调用 md2word 转 docx。
- H1标题规则:文书包名/文件标题为 H1;
- **不可在未确认前自动转**。

## 裁判者分支(stance=adjudicator,替换步骤2-3)

### C步骤2-1 确认双视角九步法均已完成【完成判据:原告/被告双九步法齐备】

核查:`intermediate/原告九步法/`、`intermediate/被告九步法/` 两侧产物齐备。
- 缺一侧 → 暂停,提示用户驱动 case-os 补齐;**裁判者不替任一方补全**(回避中立嫌疑)。

### C步骤2-2 中立合成【完成判据:四项产物齐备】

| 产物 | 输出 |
|------|------|
| **争议焦点归纳** | 对撞双方 S6,3-5个焦点,焦点层级清晰 |
| **庭审发问提纲** | 按焦点组织,每焦点 3-5 问(事实问→法律问→情境问) |
| **证据认定分析** | 三性 + 采信倾向,逐份分析(客观、可论证) |
| **裁判说理草稿** | 结构:**当事人 → 请求 → 查明事实 → 本委认为(分焦点说理) → 裁决主文骨架** |

### C步骤2-3 红线卡点(本skill最重要的一条)【完成判据:用户先定调,AI后说理】

**裁判者红线 1 — 结论先行禁令**:
> ⚠️ **AI 严禁先给裁判结论**。
> 步骤:① 输出焦点归纳 + 发问提纲 + 证据认定(三性);② **停下**,提示用户"是否支持申请人全部请求/部分支持/驳回"逐项定调;③ 用户定调前**禁止起草裁决书**;④ 用户定调后,按用户结论组织"本委认为"逐焦点说理 + 裁决主文骨架。

**任何"AI主动预判支持/不支持" 的输出 = Hard Fail**。

**裁判者红线 2 — 保密隔离**:裁判案件材料禁止沉淀进顾问轨知识库或经验卡(本skill 与 labor-audit 等顾问 skill 无知识互通)。
