# 流拍退回不消灭债权和抵押权

## R — 原文 (Reading)

> "解除查封退回，并不意味着（4个错误认识）债权消灭、抵押权消灭、利息计算中止、不能恢复执行。"
>
> — 李傲然，流拍处置

---

## I — 方法论骨架

财产流拍后拒绝抵债、解除查封退回被执行人，只是本轮处置失败：债权不消灭、抵押权不消灭、利息不停算、仍可恢复执行或待市场变化重启变价。方法论是逐项拆穿四个直觉性错误认识，防止债权人误以为"不接受抵债就丧失权利"而被迫接受不利条件。对涨价财产可申请重启变价程序；对债务人而言，流拍退回不是债务了结信号。

---

## A1 — 书中的应用 (Past Application)

### 案例 1: 三年前流拍退回的房子现在涨价
- **问题**: 债权人以为流拍退回后再也不能处置。
- **方法论的使用**: 权利存续规则——债权和抵押权均未消灭。
- **结论**: 可申请重启变价程序。
- **结果**: 市场回暖时重新获得处置机会。

### 案例 2: 拒绝抵债后的权利状态
- **问题**: 债权人担心不接受抵债会丧失担保。
- **方法论的使用**: 四个"不消灭"逐项对照。
- **结论**: 抵押权和债权继续存在，利息继续计算。
- **结果**: 债权人可以按市场节奏决策而非被迫接受。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 财产流拍且申请人犹豫是否接受抵债。
2. 多年前流拍退回的财产现在价值回升。
3. 向客户解释流拍后的权利状态和后续路径。

### 语言信号 (用户的话里出现这些就应激活)

- "流拍了怎么办"
- "不接受抵债债权还有吗"
- "退回的房子还能再拍吗"
- "利息还继续算吗"

### 与相邻 skill 的区分

- 与 `execution-offset-ruling-property-transfer` 的区别: 那个是流拍抵债裁定送达即物权变动，本 skill 是拒绝抵债退回后的权利存续规则。
- 与 `auction-price-ladder-platform` 的区别: 那个解决降价阶梯和平台合规，本 skill 解决流拍退回后的法律后果。

## E — 可执行步骤 (Execution)

1. **确认流拍分支**
   - 完成标准: 明确本案处于接受抵债/再次拍卖/退回三条路径中的哪一条。
2. **逐项核对四个不消灭**
   - 完成标准: 书面确认债权、抵押权、利息计算、恢复执行权的现状。
3. **评估重启时机**
   - 完成标准: 结合市场价值、查封状态、时效因素判断何时申请恢复或重启变价。
4. **向客户交付预期**
   - 完成标准: 用四个"不消灭"解释流拍后果，避免误判为程序终点。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 已出具以物抵债裁定，物权已变动，不存在"退回"问题。
- 用户问的是拍卖定价和平台合规，不是流拍后果。

### 作者在书中警告的失败模式

- 直觉性放弃：误以为流拍退回等于债权或抵押权消灭，错失重启机会。

### 作者的盲点 / 时代局限

- 重启变价的具体申请条件和法院审查尺度各地可能不同，需当地核实。

### 容易混淆的邻近方法论

- 与"终结执行"混淆：流拍退回是本轮处置失败，不是执行程序的终结。
