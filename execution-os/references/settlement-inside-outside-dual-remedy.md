# 执行和解内外区分与二选一救济

## R — 原文 (Reading)

> "一、区分[执行和解]与[执行外和解]：和解意图（是否提交执行法官）……三、申请人权利二选一：恢复执行，或另行起诉。""被执行人一方不履行执行和解协议的，申请执行人可以申请恢复执行原生效法律文书，也可以就履行和解协议向执行法院提起诉讼。""当事人达成以物抵债执行和解协议的，人民法院不得依据该协议做出以物抵债裁定。"
>
> — 李傲然，执行和解

---

## I — 方法论骨架

是否提交执行法官是执行内/外和解的分界线：提交了才产生执行程序中的和解效力，不提交则是普通合同。执行内和解不履行时，申请人只能在两条路中二选一——申请恢复执行原生效法律文书（扣除已履行部分），或就和解协议另行起诉；不能既恢复又起诉重复受偿。和解中的以物抵债条款换不来法院裁定：法院不得据此出具以物抵债裁定并协助过户，与司法拍卖流拍后的抵债裁定（送达即物权变动）完全不同。方法论是在签约前锁定程序轨道，在违约后按二选一规则决策。

---

## A1 — 书中的应用 (Past Application)

### 案例 1: 和解约定以房抵债后对方不过户
- **问题**: 能否申请法院强制过户。
- **方法论的使用**: 裁定禁区规则——法院不出具以物抵债裁定。
- **结论**: 不能强制过户，只能另诉或恢复原判。
- **结果**: 纠正"和解抵债=司法裁定"的误解。

### 案例 2: 和解破裂后的救济选择
- **问题**: 对方部分履行后停止，走哪条路。
- **方法论的使用**: 二选一规则，扣除已履行部分评估两条路径的效率和标的。
- **结论**: 恢复原判或另诉只能选一个。
- **结果**: 避免程序冲突和重复受偿风险。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 签订执行和解协议，决定是否提交法官备案。
2. 和解协议不履行，需要选择恢复原判或另诉。
3. 和解中包含以物抵债条款，需评估过户保障。

### 语言信号 (用户的话里出现这些就应激活)

- "和解协议要给法官吗"
- "他不履行和解怎么办"
- "以房抵债能强制过户吗"
- "恢复执行还是另诉"

### 与相邻 skill 的区分

- 与 `execution-offset-ruling-property-transfer` 的区别: 那个是流拍抵债裁定送达即物权变动，本 skill 是和解抵债无裁定的禁区规则。
- 与 `withdrawal-discretionary-termination` 的区别: 那个是撤回的程序后果，本 skill 是和解协议的效力与救济。

## E — 可执行步骤 (Execution)

1. **定性和解类型**
   - 完成标准: 明确是否提交执行法官，确定执行内/外和解身份。
2. **签约前锁定轨道**
   - 完成标准: 内和解明确备案方式；外和解评估普通合同效力和另诉路径。
3. **设计抵债条款**
   - 完成标准: 以物抵债条款写明自行过户安排和违约责任，不依赖法院裁定。
4. **违约后二选一**
   - 完成标准: 评估恢复原判（扣已履行）与另诉和解协议的效率、标的和证据，书面选定一条路径。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 流拍后的以物抵债裁定，那是另一条司法处置轨道。
- 诉讼中的调解书，本身具有强制执行力，不走执行和解规则。

### 作者在书中警告的失败模式

- 以为和解抵债能换来法院裁定和强制过户；既申请恢复又另诉造成程序冲突。

### 作者的盲点 / 时代局限

- 讲义未展开外和解另诉的具体案由和管辖细节，需另行核实。

### 容易混淆的邻近方法论

- 与"执行外和解"混淆：外和解只是普通合同，不产生中止/恢复执行的程序效果。
